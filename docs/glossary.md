## 基礎

**カーネル**
OSの中核。ハードウェアを直接操作できる唯一のプログラム。CPUの特権モードで動く。

**ユーザー空間**
普通のアプリケーションが動く領域。ハードウェアに直接触れず、必要なときはカーネルに依頼する。

**システムコール**
ユーザー空間のプログラムがカーネルに仕事を依頼する仕組み。`open`, `read`, `write`, `ioctl` など。呼ぶたびにユーザー空間とカーネルの間を往復するため、それ自体にコストがある。

**ファイルディスクリプタ (fd)**
`open` が返す整数。ファイルの実体はカーネル側にあり、ユーザー空間には整理券の番号だけが渡される。0が標準入力、1が標準出力、2が標準エラー出力。

**ioctl**
デバイスファイルに対して任意の命令を送るシステムコール。KVMの操作はすべてこれ経由。

**NIC (Network Interface Card)**
ネットワークにつなぐためのハードウェア部品。LANポートやWi-Fiチップの実体。

**仮想メモリ**
物理メモリではなく、カーネルがプロセスごとに見せているメモリ。プロセスが指し示したメモリアドレスをCPUが実際の物理アドレスに変換する。
ソフトウェアで変換をやるのではなく、ハードウェアがやっているという点がポイント。

**mmap (memory map)**
特定のメモリアドレス範囲を、どのfdのどの範囲に割り当てるかというマッピングをカーネルの対応表に書き込むシステムコール。
実際にデータをメモリに書き込むわけではない。mmap が指定したメモリ範囲に実際にアクセスし、まだそこに物理メモリが割り当てられていないと、ページフォルトが走る。そして中断したところから何事もなかったかのように再開するという仕組み。
`read` は（カーネルのページキャッシュを無視すると）、毎回 syscall を発行してコピーを都度つど発生させる。mmap は、読み込むだけであれば、ページキャッシュにあるページをそのまま仮想メモリに割り当てるだけなので、syscall すら無くす（初回のアクセスだけは必要だけど。2回目以降は無くなる）。

**ページフォルト**
仮想メモリにアクセスが走った時に、まだ物理メモリの割り当てがされていないと CPU が変換処理で例外を発行し、それをカーネルのハンドラが呼ばれ、カーネルが物理メモリの割り当てを行う仕組みのこと。

あるいは別のタイミングとして、fork された後に子プロセスが書き込む場合がある。
すでに物理メモリが割り当て済みの場合で fork した場合、親プロセスも子プロセスも同じ物理メモリを共有する。ただし、子プロセスが書き込みをする場合は、その物理メモリに書き込んでしまうと親プロセスからみたデータも書き変わって壊れてしまう。そのため、子プロセスが書き込むときは、新しく物理メモリを割り当て、そこにデータをコピーした上で子プロセスの書き込み処理が行われる。これをCopy on Writeといい、ページフォルトが起きる別のパターン。

また、ページフォルトはカーネルが行うのが基本だが、`userfaultfd` により、ユーザー空間のハンドラがページフォルトを実行することもできる。

**動的リンク**
ライブラリ(libcなど)を実行ファイルに毎回コピーしていると同じものがディスクやメモリに大量に複製することになってしまい効率が悪い。
1箇所だけ（例えば /lib/x86_64-linux-gnu/libc.so.6) 置いておき、実行時に各プロセスが、同じファイルを利用するように、それぞれの仮想アドレス空間にマッピングしておくと、物理メモリの実体は１つで済ませられる。
こうした仕組みを動的リンクと呼ぶ。この作業をする役割が、動的リンカ。

**vdso (virtual dynamic shared object)**
カーネルが全プロセスに自動でマップする特殊な領域で、ディスクに実体がない。カーネルが持っている時刻などの情報を読むだけの処理を、syscall なしで済ませるために存在している。
カーネルが時刻を書き込んでいるページを各プロセスに読み込み専用でマップしておけば、各プロセスは普通のメモリアクセスで時刻を取得できて効率が良くなる。syscall 呼び出しを減らす工夫の1つ。

## プロセスとシグナル

**プロセス**
実行中のプログラムとメモリ空間の論理的なまとまり。

**fork** ★
プロセスをコピーして新しい子プロセスを生成する。メモリ空間をコピーするが、スレッドは現在のスレッドだけ。

**exec** ★
現在のプロセスを、指定したプログラム（コマンド）で上書きして実行する。
Unix には『プログラムを起動する』という単一の操作がないため、`fork` の後に実行することになる。２段階になっていることで、子プロセスを実行する前のリソース管理などの処理を普通のコードで書くことができる。

**ABI (Application Binary Interface)** ★
コンパイル後の機械語レベルでのプログラム間のデータのやり取りの約束。Rust でCの関数を呼び出したり、逆にCやカーネルからRustのコードを呼び出す時に必要。（APIはソースコードレベルの約束）

たとえば文字列は、Rustでは`&str`は文字列のポインタと長さを保持しているが、Cではポインタだけであるので、メモリの載せ方が違う。また、関数の呼び出しについても、引数をどのレジスタに置くか、戻り先アドレスをどこに積むかなど、事前に合意しておく必要があるものがある。それらを定義したものが ABI。

**終了コード**
プログラムが終了した理由を意味する 0~255 の整数値。125,126,127などの数値にどういう意味があるかはシェル業界の慣習で決まっている。

**パイプ**
プロセス間でデータを読み書きすることのできるデータ構造。読み込み側と書き込み側の fd が1つずつある。
パイプには容量があり(64KiB)、詰まると読み書きがブロックされる（ read しないと、write できない）。

**EOF (End Of File)** ★
パイプがもうデータを返さない（すべて read した）という合図。パイプの書き込み側の fd が1つでも残っていれば、まだ書き込まれる可能性があると判断され、EOFを返さない。プロセスの終了ではないという点が注意。

**シグナル**
プロセス間通信を実現するために送ったり、カーネルからプロセスに合図を出すために使われる信号。シグナルハンドラを定義でき、これは今のスレッドに割り込んで、シグナルに対応した処理を実行することができる。

**async-signal-safe** ★
シグナルハンドラの中から呼んでも安全という性質のこと。スレッドセーフとは違う。処理の途中という概念がないということ。
シグナルハンドラは別スレッドでの実行ではなく、今のスレッドに割り込んで走るので、割り込まれた自分自身が途中の状態でも壊れないことが必要。
`AtomicBool` は1つのCPU命令で実行できるため、async-signal-safe の例となっている。

**プロセスグループ**
複数のプロセスをまとめたもの。`kill` では、PIDにマイナス(`-`)をつけることで、プロセスグループに属する複数プロセスに対してまとめてシグナルを送ることができる。

**SIGTERM と SIGKILL**
SIGTERM はプロセスに終了の合図を送る。シグナルハンドラでキャッチして処理を実行できる。
SIGKILL もプロセスに終了の合図を送るが、SIGTERM と違い、シグナルハンドラでキャッチができない。

**コアダンプ**
死んだ瞬間のプロセスのメモリを丸ごとファイルに書き出したもの。Phase 6 のスナップショットと同じ形をしている。

**ページ**
仮想メモリ・物理メモリの変換と権限の単位のこと。Linuxでは通常、4KiB。
1B毎に読み書きをすることにすると、ページテーブルのエントリが大量になってしまうため、4KiB = 4096B 毎にすることで、
ページテーブルのエントリを1/4096にしている。

なお、4KiB = 2^12B = 0x1000 なので、アドレスの下3桁はいつも変わらない。仮想・物理の変換をしても。

**KiB と kB**

- KiB = 2^10 B
- kB = 1000 B

`/proc` では `kB` と表記されているが、実際には 2^10B を意味しているらしい。歴史的経緯。

ページもアドレス空間も2の累乗の大きさなので、キリの良い 4KiB, 1GiB などを使う方が便利。

**VSZ と RSS**

- VSZ = VmSize
    - プロセスが予約しているメモリ領域のサイズ。mmap した時にこれが増える。
- RSS = VmRSS
    - 実際に物理メモリに割り当てられているメモリ領域のサイズ。mmap しただけではこの値は増えず、ページフォルトが起きて物理メモリが割り当てられるとこれが増える。
    - fork したときも子プロセスが同じ物理メモリを指しているので、RSSも親プロセスと同じ値になり、物理メモリがシステム全体で増えたように見える時があるが、実際には増えていないので注意。他の指標(Pssなど)を併せて見るべき。

**VMA (Virtual Memory Area)**

- `/proc/self/maps` の1行のこと。
- カーネルが読み書きするデータで、予約ずみの仮想メモリ領域が、どんな権限で、どこに割り当てられているか(あるいはどこにも割り当てられていないか)を管理している。
- ページテーブルはCPU（ハードウェア）が読むデータという意味で、VMAとは異なる。(ページテーブルの詳細は後述)

**ページテーブル** ★

- 仮想メモリがどの物理メモリに割り当てられているかの対応を管理しているデータ。
- CPU（ハードウェア）はこれを読んで処理を実施する。
- ページフォルトが起きた時に、カーネルがページテーブルに対応を書き込む。
- `proc/self/pagemap` で8バイト毎にページの情報が格納されている（後述）が、その8バイトの中の下位55ビットが物理メモリ(のページ番号)であるので、pagemap はページテーブルと似たデータであることがわかる。（似てるだけ？）
- EPT ってなんだ？？？

**PFN (Page Frame Number)**
pagemap のエントリーの下位55ビットのこと。物理メモリのページ番号である。
4096倍すると、そのページの先頭の物理アドレスになる。

**遅延割り当て** ★
mmap した時は仮想アドレスをどこに対応させるかを予約するだけであり、例えばファイルに割り当てても、実際にはファイルは読み込まれない。
そのメモリにアクセスするときに、まだ物理メモリが割り当てられていないとカーネル（あるいは userfaultfd ハンドラ）が気づいて、物理メモリを割り当てられたときに、割り当てが起きる。この時に初めて読み込みが行われる。

**ゼロページ**
割り当て先なし（匿名）で mmap しただけのページを、書き込みせずに読み込んだ場合、カーネルは「これはまだ書き込みがされておらず、匿名なので、ゼロを返せば良い」と判断できる。この時、毎回新しい物理メモリを割り当てて、そこにゼロを書き込むのではなく、ゼロが書き込まれた物理メモリをシステム全体で用意しておき、毎回この物理メモリを割り当てれば、利用する物理メモリを少なく済ませられる。このページをゼロページという。

**CoW (Copy-on-Write)** ★
プロセスを fork した時、VMA もコピーされるが、仮想アドレスに対応する物理アドレスはそのままで、新しい物理アドレスが割り当てられるわけではない。
プロセスが読み込みをした時も、その物理アドレスに対して読み込みが行われる。
実は、カーネルは fork した時に、親子両方のページテーブルのエントリを読み取り専用にする（VMAでは書き込み可のまま）。
そのため、親と子どちらかのプロセスが書き込みをしたときは、ページフォルトが起きて、元の物理メモリから新しい物理メモリにコピーが行われ、その後に書き込みが実施される。この遅延の仕組みが CoW と呼ばれる。
親から見ても子から見ても、物理メモリには割り当て済みではあるので、RSSでは見えにくい（両者とも同じ値になる）。

**ガードページ**
VMA のなかに `---p` という権限で確保されている匿名ページがある。
あるプログラムがバグで想定より外のメモリ領域にアクセスしてしまった場合に、このようなページがあれば、権限がないことでプログラムを異常終了させることができ、メモリが壊れることを防ぐことができる。
このような意図で確保されているページを、ガードページという。
単に確保せずに、ただ仮想アドレス領域の中の"穴"を用意しておくだけだと、他の処理で別の目的で mmap で確保される可能性があるため、明示的に確保しておくことが重要。

権限がページテーブルの1ページ単位でしか設定できないため、ガードページも1ページで確保する。

**brk と `[heap]`**

- brk
    - プログラムの扱うメモリのうち、目的に応じてセグメントという単位で分けられたりする。
    - そのうち、bss 領域の外側を伸縮することのできるシステムコールを brk という。
    - 伸縮させて領域を確保し、malloc が要求するヒープ領域を確保することもできる（が、実際にはかなり小さい領域でのみ brk を使うらしい）
    - bss 領域の外側を伸縮させるだけなので、仮にその確保された領域の中間らへんのメモリが空いて、OSに物理メモリを返却したい場合でも、他に利用中のメモリがあると、物理メモリを返却できない（縮めることしかできないから）ので、物理メモリを効率的に使えないことがある。
- `[heap]`
    - brk で確保されるメモリ領域のこと。
    - malloc で要求されるヒープメモリは、brk で確保した `[heap]` を割り当てることもある。が、mmap で確保したメモリを割り当てることもあるし、そもそも malloc は libc の関数でユーザー空間の話なので、カーネルに戻さずに malloc が自分で管理してるメモリをそのまま割り当てることもある。

**ASLR (Address Space Layout Randomization)**

アドレスを確保する位置を毎回ランダムにずらす仕組み。
アドレス配置が固定だと、そのアドレスを決め打ちで攻撃することが可能になるため、それを回避する仕組み。

## 仮想化の基礎

**ホスト / ゲスト**
ホストは本物のマシンとその上のOS。ゲストはその中で動かされる側のOS一式。**ゲストは自分がゲストであることを知らない。**

**VMM (Virtual Machine Monitor) / ハイパーバイザ**
ゲストに対してハードウェアのフリをするプログラム。ユーザー空間で動く。QEMU、Firecracker、そしてこのプロジェクトで自作するもの。

**KVM (Kernel-based Virtual Machine)**
Linuxカーネルに組み込まれた仮想化の部品。CPUのゲストモードの出し入れと、メモリの対応付けを担当する。ユーザー空間からは `/dev/kvm` を開いて `ioctl` で操作する。デバイスのエミュレーションはKVMの担当ではなくVMMの担当。

**VT-x / AMD-V**
CPUに備わった仮想化支援機能の名前。Intel製がVT-x、AMD製がAMD-V。ゲスト専用の実行モードを提供する。

**ゲストモード**
CPUの3つ目の実行モード。この状態ではゲストのコードが本物のCPU上でネイティブ速度で実行され、ハードウェアを触ろうとする命令だけ自動的にホストへ制御が戻る。

**VM exit**
ゲストモードから抜けてホスト側に制御が戻ること。`ioctl(KVM_RUN)` から戻ってくる形で観測される。CPUのモード切り替えを伴うためコストがある。**システムコールの往復と構造が似ている。**

**trap-and-emulate**
ほとんどの命令はそのまま実行させ、危ない命令だけ捕まえてソフトウェアで辻褄を合わせる方式。仮想化の基本戦略。

**vCPU**
ゲストから見えるCPU。実体は**ホスト側の1本のスレッド**。そのスレッドが `KVM_RUN` を呼んでいる間だけ、乗っている物理CPUがゲストの命令を実行している。スレッドなので物理コア数より多く作れる。

**ゲスト物理メモリ**
ゲストが「これが自分の搭載メモリだ」と認識している領域。実体はVMMがホスト側で確保したメモリで、`KVM_SET_USER_MEMORY_REGION` でKVMに登録する。

**EPT (Extended Page Table)**
ゲストの物理アドレスをホストの物理アドレスに変換するCPUの機能。これが無かった時代はソフトウェアで変換テーブルを管理していた(shadow page table)。

**PIO / MMIO**
ゲストがデバイスとやり取りする2つの方式。PIOは専用のI/O命令(`in`/`out`)、MMIOは特定のメモリアドレスへの読み書き。どちらもVM exitを引き起こす。

**準仮想化 (paravirtualization)**
ゲスト側に「自分は仮想環境にいる」と分かっている専用ドライバを入れて、効率よくやり取りする方式。virtioがこれ。

**virtio**
準仮想化デバイスの標準規格。virtio-blk(ディスク)、virtio-net(NIC)、virtio-vsock(通信路)など。ホストとゲストで共有するリングバッファ(virtqueue)にデータを置き、通知だけを送ることでVM exitを減らす。

**virtqueue**
virtioでホストとゲストがデータをやり取りする共有リングバッファ。descriptor table / available ring / used ring の3要素からなる。

**ioeventfd / irqfd**
virtioの通知をVM exitなしで処理するための仕組み。exitの回数を減らすために使う。

**microVM**
デバイスをvirtioの最小限に絞ったVM。BIOSもグラフィックもUSBもない。起動が速く、コードが小さいため攻撃面も小さい。Firecrackerがこれ。

**nested virtualization**
VMの中でさらにVMを動かすこと。クラウドのインスタンスは既にVMなので、その中で`/dev/kvm`を使うには外側のハイパーバイザの対応が必要。

## OS-level 隔離(コンテナ側)

**namespace**
プロセス一覧やファイルシステムなどの「見える範囲」を隔離するLinuxカーネルの機能。PID / mount / net / user / uts / ipc など。

**cgroup**
CPUやメモリの使用量に上限をかけるLinuxカーネルの機能。v2ではファイルシステム経由で操作する。

**seccomp**
プロセスが呼べるシステムコールを制限する仕組み。許可が必要だったsyscallの数が、そのまま攻撃面のサイズを表す。

**共有カーネル**
コンテナはホストとカーネルを共有している。だからカーネルのバグは隔離を突破しうる。VMはゲスト自身のカーネルを持つため、この点が根本的に異なる。

## FaaS

**コールドスタート**
関数を実行するために、ゼロから実行環境を用意する時間。Lambdaの技術的な核心はこれをいかに短くするか。

**スナップショット / リストア**
起動済みVMのCPU状態とメモリを丸ごと保存し、そこから復元する仕組み。通常のブートより桁違いに速い。ただし多重復元には乱数・時刻・ネットワークアドレスの重複という危険がある。

**userfaultfd**
ページフォルトをカーネルに任せるのではなく、ユーザー空間で自分が定義したハンドラでページフォルトを制御する仕組みのこと。
ページフォルトでは、読み書きをするスレッドを一旦カーネルが眠らせ、ページフォルトが完了したタイミングで処理を再開する仕組みのため、ハンドラは別スレッド（あるいは別プロセス）で実行する必要がある。

カーネルがページフォルトを実行する場合は、単にその読み書きがあったページに対してだけ割り当てをするが、userfaultfd を使えば、例えばネットワークの向こうにあるデータを割り当てたり、読み書きされたページ以外を前もって割り当てるなど、柔軟なことができる。一方で、カーネルとユーザー空間の往復が発生するため、カーネルがページフォルトを実行するよりも、一回あたりの処理は遅くなる。

**jailer**
Firecracker本体をさらにコンテナ技術(chroot、cgroup、ユーザー切り替え)で閉じ込める補助ツール。VMMそのものが破られた場合の二重の防御。
