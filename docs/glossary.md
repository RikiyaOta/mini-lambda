## 基礎

**カーネル**
OSの中核。ハードウェアを直接操作できる唯一のプログラム。CPUの特権モードで動く。

**ユーザー空間**
普通のアプリケーションが動く領域。ハードウェアに直接触れず、必要なときはカーネルに依頼する。

**システムコール**
ユーザー空間のプログラムがカーネルに仕事を依頼する仕組み。`open`, `read`, `write`, `ioctl` など。呼ぶたびにユーザー空間とカーネルの間を往復するため、それ自体にコストがある。

**ファイルディスクリプタ (fd)**
`open` が返す整数。ファイルの実体はカーネル側にあり、ユーザー空間には整理券の番号だけが渡される。0が標準入力、1が標準出力、2が標準エラー出力。

**ioctl**
デバイスファイルに対して任意の命令を送るシステムコール。KVMの操作はすべてこれ経由。

**NIC (Network Interface Card)**
ネットワークにつなぐためのハードウェア部品。LANポートやWi-Fiチップの実体。

## 仮想化の基礎

**ホスト / ゲスト**
ホストは本物のマシンとその上のOS。ゲストはその中で動かされる側のOS一式。**ゲストは自分がゲストであることを知らない。**

**VMM (Virtual Machine Monitor) / ハイパーバイザ**
ゲストに対してハードウェアのフリをするプログラム。ユーザー空間で動く。QEMU、Firecracker、そしてこのプロジェクトで自作するもの。

**KVM (Kernel-based Virtual Machine)**
Linuxカーネルに組み込まれた仮想化の部品。CPUのゲストモードの出し入れと、メモリの対応付けを担当する。ユーザー空間からは `/dev/kvm` を開いて `ioctl` で操作する。デバイスのエミュレーションはKVMの担当ではなくVMMの担当。

**VT-x / AMD-V**
CPUに備わった仮想化支援機能の名前。Intel製がVT-x、AMD製がAMD-V。ゲスト専用の実行モードを提供する。

**ゲストモード**
CPUの3つ目の実行モード。この状態ではゲストのコードが本物のCPU上でネイティブ速度で実行され、ハードウェアを触ろうとする命令だけ自動的にホストへ制御が戻る。

**VM exit**
ゲストモードから抜けてホスト側に制御が戻ること。`ioctl(KVM_RUN)` から戻ってくる形で観測される。CPUのモード切り替えを伴うためコストがある。**システムコールの往復と構造が似ている。**

**trap-and-emulate**
ほとんどの命令はそのまま実行させ、危ない命令だけ捕まえてソフトウェアで辻褄を合わせる方式。仮想化の基本戦略。

**vCPU**
ゲストから見えるCPU。実体は**ホスト側の1本のスレッド**。そのスレッドが `KVM_RUN` を呼んでいる間だけ、乗っている物理CPUがゲストの命令を実行している。スレッドなので物理コア数より多く作れる。

**ゲスト物理メモリ**
ゲストが「これが自分の搭載メモリだ」と認識している領域。実体はVMMがホスト側で確保したメモリで、`KVM_SET_USER_MEMORY_REGION` でKVMに登録する。

**EPT (Extended Page Table)**
ゲストの物理アドレスをホストの物理アドレスに変換するCPUの機能。これが無かった時代はソフトウェアで変換テーブルを管理していた(shadow page table)。

**PIO / MMIO**
ゲストがデバイスとやり取りする2つの方式。PIOは専用のI/O命令(`in`/`out`)、MMIOは特定のメモリアドレスへの読み書き。どちらもVM exitを引き起こす。

**準仮想化 (paravirtualization)**
ゲスト側に「自分は仮想環境にいる」と分かっている専用ドライバを入れて、効率よくやり取りする方式。virtioがこれ。

**virtio**
準仮想化デバイスの標準規格。virtio-blk(ディスク)、virtio-net(NIC)、virtio-vsock(通信路)など。ホストとゲストで共有するリングバッファ(virtqueue)にデータを置き、通知だけを送ることでVM exitを減らす。

**virtqueue**
virtioでホストとゲストがデータをやり取りする共有リングバッファ。descriptor table / available ring / used ring の3要素からなる。

**ioeventfd / irqfd**
virtioの通知をVM exitなしで処理するための仕組み。exitの回数を減らすために使う。

**microVM**
デバイスをvirtioの最小限に絞ったVM。BIOSもグラフィックもUSBもない。起動が速く、コードが小さいため攻撃面も小さい。Firecrackerがこれ。

**nested virtualization**
VMの中でさらにVMを動かすこと。クラウドのインスタンスは既にVMなので、その中で`/dev/kvm`を使うには外側のハイパーバイザの対応が必要。

## OS-level 隔離(コンテナ側)

**namespace**
プロセス一覧やファイルシステムなどの「見える範囲」を隔離するLinuxカーネルの機能。PID / mount / net / user / uts / ipc など。

**cgroup**
CPUやメモリの使用量に上限をかけるLinuxカーネルの機能。v2ではファイルシステム経由で操作する。

**seccomp**
プロセスが呼べるシステムコールを制限する仕組み。許可が必要だったsyscallの数が、そのまま攻撃面のサイズを表す。

**共有カーネル**
コンテナはホストとカーネルを共有している。だからカーネルのバグは隔離を突破しうる。VMはゲスト自身のカーネルを持つため、この点が根本的に異なる。

## FaaS

**コールドスタート**
関数を実行するために、ゼロから実行環境を用意する時間。Lambdaの技術的な核心はこれをいかに短くするか。

**スナップショット / リストア**
起動済みVMのCPU状態とメモリを丸ごと保存し、そこから復元する仕組み。通常のブートより桁違いに速い。ただし多重復元には乱数・時刻・ネットワークアドレスの重複という危険がある。

**userfaultfd**
ページフォルトをユーザー空間で処理する仕組み。スナップショット復元時に、必要なページだけを遅延ロードするために使う。

**jailer**
Firecracker本体をさらにコンテナ技術(chroot、cgroup、ユーザー切り替え)で閉じ込める補助ツール。VMMそのものが破られた場合の二重の防御。
